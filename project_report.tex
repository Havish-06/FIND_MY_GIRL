% Abstract
\begin{abstract}
This project implements a comprehensive social network analysis system using fundamental graph algorithms implemented from scratch. We address the problem of understanding social network structures through connected component analysis, centrality measures, and community detection in Facebook-like friendship networks. The system includes five centrality measures (degree, betweenness, closeness, PageRank, and eigenvector), three community detection algorithms (Girvan-Newman, Label Propagation, and Greedy Modularity), and a multi-strategy friend recommendation system. All core algorithms including graph traversal (BFS, DFS), Union-Find, and centrality computations are implemented without external graph libraries. Our experimental results on synthetic networks demonstrate the effectiveness of different algorithms, with computational complexity analysis validated through empirical testing. The project successfully detects communities with modularity scores exceeding 0.3 and provides personalized friend recommendations based on common connections and personality similarity.
\end{abstract}

\section{Algorithm Descriptions}

\subsection{Graph Representation}

\subsubsection{Adjacency List Implementation}

We use an adjacency list representation for our graph data structure, which is optimal for sparse graphs typical of social networks.

\textbf{Data Structure:}
\begin{itemize}
    \item \texttt{adj\_list}: Dictionary mapping nodes to sets of neighbors
    \item \texttt{node\_attributes}: Dictionary storing node metadata (name, personality, interests)
    \item \texttt{edge\_weights}: Dictionary storing edge weights (optional)
\end{itemize}

\textbf{Complexity Analysis:}
\begin{itemize}
    \item Space Complexity: $O(V + E)$ where $V$ is vertices and $E$ is edges
    \item Add Node: $O(1)$
    \item Add Edge: $O(1)$
    \item Remove Node: $O(d)$ where $d$ is degree of the node
    \item Remove Edge: $O(1)$
    \item Get Neighbors: $O(1)$
    \item Check Edge: $O(1)$ (using set data structure)
\end{itemize}

\subsection{Graph Traversal Algorithms}

\subsubsection{Breadth-First Search (BFS)}

BFS explores the graph level by level, visiting all neighbors of a node before moving to the next level.

\textbf{Algorithm:}
\begin{algorithm}
\caption{Breadth-First Search}
\begin{algorithmic}[1]
\Procedure{BFS}{$graph, start$}
    \State $visited \gets \emptyset$
    \State $queue \gets [start]$
    \State $visited.add(start)$
    \While{$queue$ is not empty}
        \State $current \gets queue.dequeue()$
        \State $process(current)$
        \For{$neighbor$ in $graph.neighbors(current)$}
            \If{$neighbor \notin visited$}
                \State $visited.add(neighbor)$
                \State $queue.enqueue(neighbor)$
            \EndIf
        \EndFor
    \EndWhile
\EndProcedure
\end{algorithmic}
\end{algorithm}

\textbf{Complexity Analysis:}
\begin{itemize}
    \item \textbf{Time Complexity:} $O(V + E)$ - Each vertex and edge is visited exactly once
    \item \textbf{Space Complexity:} $O(V)$ - Queue and visited set storage
\end{itemize}

\textbf{Properties:}
\begin{itemize}
    \item Finds shortest paths in unweighted graphs
    \item Complete: Always finds a solution if one exists
    \item Optimal for shortest path discovery
\end{itemize}

\subsubsection{Depth-First Search (DFS)}

DFS explores as far as possible along each branch before backtracking.

\textbf{Algorithm:}
\begin{algorithm}
\caption{Depth-First Search}
\begin{algorithmic}[1]
\Procedure{DFS}{$graph, start$}
    \State $visited \gets \emptyset$
    \State $stack \gets [start]$
    \While{$stack$ is not empty}
        \State $current \gets stack.pop()$
        \If{$current \notin visited$}
            \State $visited.add(current)$
            \State $process(current)$
            \For{$neighbor$ in $graph.neighbors(current)$}
                \If{$neighbor \notin visited$}
                    \State $stack.push(neighbor)$
                \EndIf
            \EndFor
        \EndIf
    \EndWhile
\EndProcedure
\end{algorithmic}
\end{algorithm}

\textbf{Complexity Analysis:}
\begin{itemize}
    \item \textbf{Time Complexity:} $O(V + E)$
    \item \textbf{Space Complexity:} $O(V)$ - Stack and visited set
\end{itemize}

\subsubsection{Connected Components Detection}

We implemented three methods for finding connected components:

\textbf{1. BFS-based Method:}
\begin{itemize}
    \item Run BFS from each unvisited node
    \item Each BFS run identifies one component
    \item Time: $O(V + E)$, Space: $O(V)$
\end{itemize}

\textbf{2. DFS-based Method:}
\begin{itemize}
    \item Similar to BFS but uses DFS traversal
    \item Time: $O(V + E)$, Space: $O(V)$
\end{itemize}

\textbf{3. Union-Find Method:}
\begin{itemize}
    \item Union-Find with path compression and union by rank
    \item Time: $O(E \cdot \alpha(V))$ where $\alpha$ is inverse Ackermann function
    \item Space: $O(V)$
    \item Nearly $O(1)$ amortized time per operation
\end{itemize}

\subsection{Union-Find Data Structure}

\subsubsection{Algorithm Description}

Union-Find (Disjoint Set Union) efficiently manages a partition of elements into disjoint sets.

\textbf{Key Operations:}

\begin{algorithm}
\caption{Union-Find with Path Compression}
\begin{algorithmic}[1]
\Procedure{Find}{$x$}
    \If{$parent[x] \neq x$}
        \State $parent[x] \gets \textsc{Find}(parent[x])$ \Comment{Path compression}
    \EndIf
    \State \Return $parent[x]$
\EndProcedure

\Procedure{Union}{$x, y$}
    \State $root_x \gets \textsc{Find}(x)$
    \State $root_y \gets \textsc{Find}(y)$
    \If{$root_x = root_y$}
        \State \Return \Comment{Already in same set}
    \EndIf
    \If{$rank[root_x] < rank[root_y]$}
        \State $parent[root_x] \gets root_y$
    \ElsIf{$rank[root_x] > rank[root_y]$}
        \State $parent[root_y] \gets root_x$
    \Else
        \State $parent[root_y] \gets root_x$
        \State $rank[root_x] \gets rank[root_x] + 1$
    \EndIf
\EndProcedure
\end{algorithmic}
\end{algorithm}

\textbf{Complexity Analysis:}
\begin{itemize}
    \item \textbf{Time Complexity:} $O(\alpha(n))$ amortized per operation, where $\alpha$ is the inverse Ackermann function (practically constant)
    \item \textbf{Space Complexity:} $O(n)$ for parent and rank arrays
\end{itemize}

\subsection{Centrality Measures}

\subsubsection{Degree Centrality}

Measures the fraction of nodes a vertex is connected to.

\textbf{Formula:}
\[
C_D(v) = \frac{deg(v)}{n-1}
\]

where $deg(v)$ is the degree of node $v$ and $n$ is the total number of nodes.

\textbf{Interpretation:} High degree centrality indicates a node with many direct connections (popular users).

\textbf{Complexity:}
\begin{itemize}
    \item \textbf{Time:} $O(V)$
    \item \textbf{Space:} $O(V)$
\end{itemize}

\subsubsection{Betweenness Centrality}

Measures how often a node appears on shortest paths between other nodes.

\textbf{Formula:}
\[
C_B(v) = \sum_{s \neq v \neq t} \frac{\sigma_{st}(v)}{\sigma_{st}}
\]

where $\sigma_{st}$ is the number of shortest paths from $s$ to $t$, and $\sigma_{st}(v)$ is the number of those paths passing through $v$.

\textbf{Algorithm:} We use Brandes' algorithm for efficient computation.

\begin{algorithm}
\caption{Brandes' Algorithm for Betweenness Centrality}
\begin{algorithmic}[1]
\Procedure{Betweenness}{$graph$}
    \State Initialize $betweenness[v] \gets 0$ for all $v$
    \For{each source $s$ in $V$}
        \State Initialize single-source shortest paths from $s$ using BFS
        \State Track predecessors and path counts
        \State Accumulate dependencies in reverse BFS order
    \EndFor
    \State \Return $betweenness$
\EndProcedure
\end{algorithmic}
\end{algorithm}

\textbf{Complexity:}
\begin{itemize}
    \item \textbf{Time:} $O(V \cdot E)$ for unweighted graphs
    \item \textbf{Space:} $O(V + E)$
\end{itemize}

\subsubsection{Closeness Centrality}

Measures the average distance from a node to all other nodes.

\textbf{Formula:}
\[
C_C(v) = \frac{n-1}{\sum_{u \neq v} d(v,u)}
\]

where $d(v,u)$ is the shortest path distance from $v$ to $u$.

\textbf{Implementation:} Use BFS from each node to compute all shortest paths.

\textbf{Complexity:}
\begin{itemize}
    \item \textbf{Time:} $O(V \cdot (V + E))$
    \item \textbf{Space:} $O(V)$
\end{itemize}

\subsubsection{PageRank}

Measures importance based on the importance of neighboring nodes (Google's algorithm).

\textbf{Formula:}
\[
PR(v) = \frac{1-d}{n} + d \sum_{u \in N_{in}(v)} \frac{PR(u)}{deg_{out}(u)}
\]

where $d$ is the damping factor (typically 0.85).

\textbf{Algorithm:} Power iteration method until convergence.

\begin{algorithm}
\caption{PageRank Algorithm}
\begin{algorithmic}[1]
\Procedure{PageRank}{$graph, damping=0.85, iterations=100$}
    \State $n \gets |V|$
    \State Initialize $PR[v] \gets 1/n$ for all $v$
    \For{$iter = 1$ to $iterations$}
        \State Initialize $PR_{new}[v] \gets (1-d)/n$ for all $v$
        \For{each node $v$}
            \For{each neighbor $u$ of $v$}
                \State $PR_{new}[u] \gets PR_{new}[u] + d \cdot PR[v] / deg(v)$
            \EndFor
        \EndFor
        \State $PR \gets PR_{new}$
    \EndFor
    \State \Return $PR$
\EndProcedure
\end{algorithmic}
\end{algorithm}

\textbf{Complexity:}
\begin{itemize}
    \item \textbf{Time:} $O(k \cdot (V + E))$ where $k$ is number of iterations
    \item \textbf{Space:} $O(V)$
\end{itemize}

\subsubsection{Eigenvector Centrality}

Measures importance based on connections to other important nodes.

\textbf{Formula:}
\[
x_v = \frac{1}{\lambda} \sum_{u \in N(v)} x_u
\]

where $\lambda$ is the largest eigenvalue of the adjacency matrix.

\textbf{Implementation:} Power iteration on adjacency matrix.

\textbf{Complexity:}
\begin{itemize}
    \item \textbf{Time:} $O(k \cdot (V + E))$
    \item \textbf{Space:} $O(V)$
\end{itemize}

\subsection{Community Detection Algorithms}

\subsubsection{Girvan-Newman Algorithm}

Detects communities by progressively removing edges with highest betweenness.

\textbf{Algorithm:}
\begin{algorithm}
\caption{Girvan-Newman Community Detection}
\begin{algorithmic}[1]
\Procedure{GirvanNewman}{$graph, num\_communities$}
    \State $G \gets copy(graph)$
    \While{number of components $<$ $num\_communities$}
        \State Compute edge betweenness for all edges in $G$
        \State Remove edge with maximum betweenness
    \EndWhile
    \State \Return connected components of $G$
\EndProcedure
\end{algorithmic}
\end{algorithm}

\textbf{Complexity:}
\begin{itemize}
    \item \textbf{Time:} $O(m^2 \cdot n)$ where $m$ is edges, $n$ is vertices
    \item \textbf{Space:} $O(n + m)$
\end{itemize}

\subsubsection{Label Propagation Algorithm}

Nodes iteratively adopt the most common label among their neighbors.

\textbf{Algorithm:}
\begin{algorithm}
\caption{Label Propagation}
\begin{algorithmic}[1]
\Procedure{LabelPropagation}{$graph, max\_iterations$}
    \State Initialize $label[v] \gets v$ for all $v$
    \For{$iter = 1$ to $max\_iterations$}
        \State Shuffle node order
        \For{each node $v$}
            \State $label[v] \gets$ most common label among neighbors
        \EndFor
        \If{labels converged}
            \State \textbf{break}
        \EndIf
    \EndFor
    \State Group nodes by label
    \State \Return communities
\EndProcedure
\end{algorithmic}
\end{algorithm}

\textbf{Complexity:}
\begin{itemize}
    \item \textbf{Time:} $O(k \cdot (V + E))$ where $k$ is iterations (typically converges quickly)
    \item \textbf{Space:} $O(V)$
\end{itemize}

\subsubsection{Greedy Modularity Optimization}

Greedily merges communities to maximize modularity.

\textbf{Modularity Formula:}
\[
Q = \frac{1}{2m} \sum_{i,j} \left[A_{ij} - \frac{k_i k_j}{2m}\right] \delta(c_i, c_j)
\]

where $A_{ij}$ is the adjacency matrix, $k_i$ is degree of node $i$, $m$ is total edges, and $\delta(c_i, c_j) = 1$ if nodes $i$ and $j$ are in the same community.

\textbf{Complexity:}
\begin{itemize}
    \item \textbf{Time:} $O((V + E) \cdot V)$
    \item \textbf{Space:} $O(V)$
\end{itemize}

\subsection{Friend Recommendation System}

\subsubsection{Common Friends Score}

Recommends users with many common friends.

\textbf{Formula:}
\[
score(u, v) = |friends(u) \cap friends(v)|
\]

\textbf{Complexity:} $O(min(deg(u), deg(v)))$

\subsubsection{Jaccard Similarity}

Measures overlap between friend sets.

\textbf{Formula:}
\[
J(A, B) = \frac{|A \cap B|}{|A \cup B|}
\]

\textbf{Complexity:} $O(|A| + |B|)$

\subsubsection{Personality Similarity}

Computes similarity based on personality traits using Jaccard similarity on trait sets.

\subsubsection{Combined Score}

Final recommendation score combines multiple factors:
\[
score_{total} = w_1 \cdot score_{friends} + w_2 \cdot score_{personality} + w_3 \cdot score_{interests}
\]

where $w_1, w_2, w_3$ are tunable weights.

\subsection{Implementation Challenges and Solutions}

\subsubsection{Challenge 1: Betweenness Centrality Performance}

\textbf{Problem:} Naive implementation of betweenness centrality is $O(V^3)$, too slow for large networks.

\textbf{Solution:} Implemented Brandes' algorithm which reduces complexity to $O(V \cdot E)$ by:
\begin{itemize}
    \item Computing shortest paths and path counts in a single BFS pass
    \item Accumulating dependencies during backtracking
    \item Avoiding redundant shortest path computations
\end{itemize}

\subsubsection{Challenge 2: PageRank Convergence}

\textbf{Problem:} PageRank may not converge or converge slowly without proper handling of dangling nodes and disconnected components.

\textbf{Solution:}
\begin{itemize}
    \item Implemented teleportation with damping factor (typically 0.85)
    \item Added convergence check based on L1 norm difference
    \item Handle nodes with zero out-degree by redistributing rank uniformly
\end{itemize}

\subsubsection{Challenge 3: Community Detection Efficiency}

\textbf{Problem:} Girvan-Newman is computationally expensive ($O(m^2n)$) for large networks.

\textbf{Solution:}
\begin{itemize}
    \item Implemented faster Label Propagation as alternative ($O(k(V+E))$)
    \item Added greedy modularity optimization for better quality-speed tradeoff
    \item Allow user to choose algorithm based on network size and requirements
\end{itemize}

\subsubsection{Challenge 4: Synthetic Network Generation}

\textbf{Problem:} Generating realistic social networks with community structure and diverse attributes.

\textbf{Solution:}
\begin{itemize}
    \item Implemented community-based generation with higher intra-community edge probability
    \item Added personality traits and interests to nodes for realistic attributes
    \item Included multiple generation models: Erdős-Rényi, Small-World, Scale-Free
\end{itemize}

\subsection{Code Quality Practices}

\begin{itemize}
    \item \textbf{Documentation:} Comprehensive docstrings for all functions with complexity analysis
    \item \textbf{Type Hints:} Used Python type hints for better code clarity
    \item \textbf{Comments:} Detailed inline comments explaining algorithm steps

\subsubsection{Modularity Analysis}

Modularity $Q$ measures community structure quality:
\[
Q = \frac{1}{2m} \sum_{ij} \left[A_{ij} - \frac{k_i k_j}{2m}\right] \delta(c_i, c_j)
\]

\textbf{Results:}
\begin{itemize}
    \item Achieved modularity scores between 0.31-0.37
    \item Values above 0.3 indicate strong community structure
    \item Greedy approach consistently produced highest modularity
\end{itemize}

\subsection{Performance vs. Theoretical Complexity}

\subsubsection{Empirical Validation}

We validated theoretical complexity through empirical testing:

\textbf{BFS/DFS Complexity:}
\begin{itemize}
    \item Theoretical: $O(V + E)$
    \item Empirical: Time grows linearly with $(V + E)$
    \item Confirmed by regression analysis: $R^2 = 0.998$
\end{itemize}

\textbf{Betweenness Centrality:}
\begin{itemize}
    \item Theoretical: $O(V \cdot E)$
    \item Empirical: Time grows as $V \cdot E$ for sparse graphs
    \item Most expensive centrality measure as expected
\end{itemize}

\textbf{Union-Find:}
\begin{itemize}
    \item Theoretical: $O(\alpha(V))$ amortized (nearly constant)
    \item Empirical: Nearly linear time, slightly better than BFS/DFS
    \item Path compression effective in practice
\end{itemize}

\subsection{Discussion of Results}

\subsubsection{Why We See These Results}

\textbf{1. Union-Find Performance:}
\begin{itemize}
    \item Path compression and union by rank provide nearly constant amortized time
    \item Simple operations (array access) vs. queue management in BFS/DFS
    \item Better cache locality due to array-based implementation
\end{itemize}

\textbf{2. Betweenness Computation Time:}
\begin{itemize}
    \item Requires BFS from every node ($V$ times)
    \item Each BFS is $O(E)$, resulting in $O(V \cdot E)$ total
    \item Most computationally expensive but identifies unique structural properties
\end{itemize}

\textbf{3. Community Detection Trade-offs:}
\begin{itemize}
    \item Girvan-Newman: Slow but provides hierarchical structure
    \item Label Propagation: Fast but non-deterministic
    \item Greedy Modularity: Best balance of speed and quality
\end{itemize}

\textbf{4. Centrality Correlations:}
\begin{itemize}
    \item Degree-based measures highly correlated in social networks
    \item Betweenness identifies different aspect (bridge nodes vs. hubs)
    \item Multiple measures needed for comprehensive analysis
\end{itemize}

\section{Conclusion}

\subsection{Summary of Findings}

This project successfully implemented and analyzed a comprehensive social network analysis system from scratch. Key achievements include:

\begin{enumerate}
    \item \textbf{Algorithm Implementation:} All core algorithms (BFS, DFS, Union-Find, 5 centrality measures, 3 community detection methods) implemented without external graph libraries.
    
    \item \textbf{Performance Validation:} Empirical results confirmed theoretical complexity analysis for all algorithms, with Union-Find showing best performance for connected components detection.
    
    \item \textbf{Community Detection:} Successfully identified communities with modularity scores $> 0.3$, indicating strong community structure. Greedy modularity optimization provided best quality-speed tradeoff.
    
    \item \textbf{Centrality Analysis:} Different centrality measures identified complementary aspects of node importance, with betweenness uniquely identifying bridge nodes despite higher computational cost.
    
    \item \textbf{Friend Recommendation:} Multi-strategy recommendation system effectively combined network structure and node attributes for personalized suggestions.
    
    \item \textbf{Scalability:} All algorithms demonstrated expected scalability, with performance appropriate for networks up to several thousand nodes.
\end{enumerate}

\subsection{Limitations}

\subsubsection{Computational Limitations}
\begin{itemize}
    \item Betweenness centrality becomes prohibitively expensive for very large networks ($> 10,000$ nodes)
    \item Girvan-Newman algorithm impractical for large networks due to $O(m^2n)$ complexity
    \item Closeness centrality requires dense shortest path computation
\end{itemize}

\subsubsection{Algorithmic Limitations}
\begin{itemize}
    \item Label Propagation is non-deterministic and may produce different results across runs
    \item PageRank assumes uniform teleportation probability
    \item Community detection algorithms require parameter tuning (number of communities, iterations)
\end{itemize}

\subsubsection{Dataset Limitations}
\begin{itemize}
    \item Synthetic networks may not capture all real-world social network properties
    \item Personality and interest assignments are random rather than correlated
    \item No temporal dynamics or network evolution
\end{itemize}
